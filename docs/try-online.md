# 설치 없이 인터넷 브라우저에서 체험하기

Node.js를 개인 컴퓨터에 설치하지 않아도 GitHub Pages로 이 앱을 사용할 수 있습니다. 정적 파일만으로 동작하고 실제 AI 키는 필요하지 않습니다.

## GitHub에서 한 번만 설정하기

무료 개인 요금제에서는 공개 저장소로 Pages를 이용할 수 있습니다. 같은 `book` 저장소를 계속 사용하며 새 저장소를 만들 필요는 없습니다.

저장소가 비공개라면 정리가 완료된 것을 확인한 후 **Settings → General → Danger Zone → Change repository visibility → Change to public**에서 공개로 변경합니다. 확인 문구는 GitHub가 화면에 요청하는 내용을 따릅니다. 공개로 변경하면 앱 코드와 공개용 문서를 누구나 볼 수 있습니다. 비공개 유지가 필요하다면 공개 변경을 하지 말고 사용 중인 요금제의 Pages 지원 여부를 확인하세요.

1. 프로젝트 소유자 계정으로 GitHub에 로그인합니다.
2. https://github.com/ram870622-pixel/book/settings/pages 를 엽니다.
3. **Build and deployment**의 **Source**를 **Deploy from a branch**로 선택합니다.
4. **Branch**는 **main**, 폴더는 **/ (root)**를 선택한 뒤 **Save**를 누릅니다.
5. 배포가 완료될 때까지 기다립니다. 같은 설정 화면에 표시되는 **Visit site**를 누릅니다. GitHub Actions 화면에서 배포 진행·실패 원인도 볼 수 있습니다.

예상 기본 주소는 `https://ram870622-pixel.github.io/book/`입니다. 이 주소는 Pages 활성화와 배포 완료 후 사용할 수 있으며, 사용자 정의 도메인 설정이 있다면 GitHub가 표시하는 실제 주소를 사용합니다.

현재 저장소는 하위 경로(`/book/`)에서도 스크립트·스타일·샘플을 불러올 수 있도록 준비했고, Jekyll 처리 없이 제공하도록 `.nojekyll`을 포함했습니다. 별도 빌드 명령은 필요하지 않습니다.

**Pages 메뉴가 없거나 요금제 안내가 보이면:** 저장소의 공개 여부·사용 중인 요금제·조직 정책에 따라 Pages 사용 가능 여부가 다릅니다. 저장소를 임의로 공개하지 말고 해당 화면의 안내를 확인하세요. 공개 저장소로 바꾸면 소스·문서도 공개됩니다.

## 처음 써보기

1. **그림책 만들기**를 누릅니다.
2. **가상 샘플 넣기**를 누릅니다.
3. 4~6페이지를 선택하고 **이야기 초안 만들기**를 누릅니다.
4. 내용을 읽고 **검토했어요 · 책에 반영**을 누릅니다.
5. 페이지 글·그림을 수정하고 **책 읽기**로 넘겨봅니다.
6. **PDF 저장**에서 PDF로 저장하거나 **내보내기**로 편집 가능한 책 파일을 보관합니다.

현재는 실제 AI가 아닌 모의 AI 예시입니다. 업로드하는 자료와 책은 브라우저에 저장되며 GitHub 서버로 전송하지 않습니다. 사이트 주소를 다른 사람에게 보내도 책 데이터는 공유되지 않습니다. 클라우드 개발 환경·다른 브라우저·다른 사이트 주소에서 만들었던 책을 옮기려면 JSON 내보내기/가져오기를 사용하세요. 초기 체험에는 가상 샘플을 사용하세요.

## 이미 제가 준비한 것과 남은 단계

- 클라우드: Node.js, npm, 의존성 설치 및 앱 실행·브라우저 검증 완료.
- 저장소: 정적 배포용 상대 경로, 샘플 자료, `.nojekyll`, 한국어 안내 포함.
- 사용자 계정 설정: GitHub Pages 활성화는 GitHub 설정 화면에서 진행해야 합니다. 이 작업 환경에서는 GitHub Pages API 접근이 거부되어 설정을 대신 변경하지 못했습니다. 비밀번호나 토큰을 채팅에 보낼 필요는 없습니다.

Pages 설정 후 소스를 main에 저장하면 GitHub가 다시 배포합니다. 클라우드 환경의 '게시' 버튼과 GitHub Pages 웹사이트 배포는 별개의 동작입니다.
